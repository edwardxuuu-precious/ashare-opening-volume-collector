# 趋势三角每日结果发布

默认页面读取私有的已发布结果，不再让每位访问者重新读取全市场日文件。每日列表仍使用默认参数、140个交易日和最近5个交易日的事件窗口。个股详情分片保留目录内全部已保存日线及缺口，当前股票名单之外但仍有历史行情的代码也可以查询。

`backend.triangles.daily` 只读取当前私有行情，不请求新行情提供者。它冻结原始目录、股票名单和每个日期对象的版本，使用带 ETag 条件的读取，并核对日期对象的生成时间与已提交目录相同。计算程序 `tooling/build-triangle-daily.mjs` 直接使用网站的 `triangle-data.ts` 和 `triangles.ts`。发布前再次核对所有源版本。原始数据更新时放弃本轮，保留上一批完整结果。

发布路径为 `data/triangles/daily/`。不可变的16位数据版本目录保存 `screening.json`、`bundle-NNN.json` 和归档清单。分片实际字节超过4 MiB时确定性缩小批次，不截断历史。对象上传后逐个回读，最后有条件地切换 `manifest.json`。读取接口只开放清单、状态和版本内的筛选/分片文件；内部租约及归档清单不向页面开放。接口保留原始JSON字节，使前端可以校验内容摘要。

`.github/workflows/triangles.yml` 在主分支采集工作流成功完成后运行。工作日北京时间17:40、21:40提供补偿触发。生成程序仍检查最新已收盘交易日是否有完整价格批次，触发时间不代表数据已经就绪。它使用独立的 `stock-triangles-daily-writer` 并发组，避免挤掉采集器待执行任务；三角结果自己的条件租约与清单条件写限制唯一发布者。所有结果绑定完整来源版本，即使检查后出现新原始批次，旧快照仍然自洽，后续触发会接续新版本。

每轮上限900秒、8个源读取工作线程、3 GiB新增源读取量、2000个目录交易日。上限触发、传输失败、引擎失败、源变动或读回不符均不发布部分名单。交易日历当前由项目既有的2026年官方日历提供；后续年份需先更新该共享日历，不能用工作日猜测替代。

本机验证和明确的恢复运行可以使用只读 `--cache-dir`。缓存日期的版本、ETag、字节数及内容摘要必须同时匹配实时来源版本，才会复用。相同来源和执行规则会直接保留已有发布版本。

```sh
python -m backend.triangles.daily --bucket "$STOCK_BUCKET" --max-seconds 900 --workers 8 --receipt /tmp/triangle-daily-receipt.json
```

自动计算完成、页面已读取和人工验收是不同状态。代码中的 `COMMITTED` 只表示整批对象已经发布并通过读回，不说明交易效果。
