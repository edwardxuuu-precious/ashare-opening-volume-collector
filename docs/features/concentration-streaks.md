# 连续筹码集中度筛选

页面为 `/concentration`，主导航“连续集中度”。本次使用当前统一UI的 `SiteHeader`、`WorkbenchPageBar`、`WorkbenchShell`、状态与分页控件，接入原 `SiteRouter`；站内切页保留已验证会话，直接访问与刷新仍经过原登录门。页面实现不等于已部署，线上状态以本轮发布回执和实际验收为准。

## 用户可见规则

固定历史换手衰减系数2，筛选90%筹码成本集中度，不套用每日筹码页的价格、涨停、主峰或稳定条件。页面分为连续下降至少3、5、10、15、20个市场交易日五组，名单允许重叠。连续下降N天需要N+1个连续市场交易日的有效读数，终点为当前已发布筹码批次的 `as_of`。

每次比较使用未四舍五入的集中度，当前值必须严格小于前一交易日。相等或上升会中断；确认无交易的当天也不能构成下降。所需日期缺失不跳过，不拿更早的成交日替换市场交易日。若窗口内存在已知持平、上升或确认无交易，已足以证明未满足，即使更早还有缺值；没有已知反例但所需点缺失则为“无法判断”。最近短窗口有效时，3天、5天可入选，而10天、15天、20天仍可能无法判断。

“≥20天”表示21个观察值已经确认20次连续下降，不能据此宣称连续天数恰好为20。遇到更早缺口时，已确认的较短连续天数也用“≥N天”表示下界。有效0%与无法计算分别保留。列表可按名称或代码搜索，按连续天数、当前集中度或所选区间降幅排序；表格、曲线与展开读数使用同一条已加载序列。

## 集中度与历史窗口

90%成本集中度为 `(Q95 − Q5) / (Q95 + Q5) × 100%`。Q5、Q95为完整价格分布从低向高累加，首次达到实际总质量5%、95%的正质量节点。价格和质量均使用模型输出原精度；界面普通读数显示两位小数，展开表保留传输数值。数值越小，估算成本价格越集中。公式参照[同花顺股民学校集中度说明](https://search.10jqka.com.cn/school/article-detail/id/3765)已可读的索引摘录，原文访问限制和软件取档差异仍保留。

模型沿用当前生产的 `chip-estimate.eastmoney-nodes150.ohlc4.zero-start.decay2.window210.v1`，不是旧校准页的固定0.01元档模型。它使用不复权行情、OHLC4三角采样、150个动态价格节点、零初始质量与系数2换手衰减，最终输出才归一化。每个日期独立取截至该日的尾210根有效历史，避免把后一批封存的209根前日前缀拼进独立历史序列。最新正常交易日独立重算的原始质量、网格与profile必须与该批封存快照一致，冲突不能生成正常入选。

历史交易轴复用项目已核对的[上交所2026年休市安排](https://www.sse.com.cn/disclosure/announcement/general/c/c_20251222_10802507.shtml)。不足21个支持日期或不支持的年份停止计算。每股先读取原已发布500根投影；投影已覆盖来源审计的全部有效输入时允许保留真正的短观察历史，否则预热不足只尝试既有SHA绑定归档。不能从首根已保存K线反推上市日；上市前仅使用可信上市事实，确认无交易仅使用已有来源证据或明确零成交量。

## 私有读取与每日刷新

`backend/chips/concentration.py` 拥有纯计算和五组结论；`concentration_runner.py` 只读取既有私有筹码目录、完整screening股票分母、逐股不可变帧及必要的已存归档。没有行情商请求，不改原runner、模型、原manifest、股票帧、旧筛选或来源对象。

处理按64股不可变分块保存至 `collector/chips/concentration/<dataset>/<input_fingerprint>/`，绑定完整来源清单、分母、交易轴、规则与数值源码闭包。缺失已被目录引用的股票帧、存储传输失败或身份冲突会停止最终发布并非零退出，不把它们转换成“已全部处理的空名单”。正常日期级数据不足保持逐点原因和每组 `PASS/FAIL/UNKNOWN`。

默认最多2个在途股票，允许1至4个；20分钟参数约束逐股接入，不预先排队整块64股。截止前30秒停止新RPC接入；S3连接5秒、空闲读取10秒、单次尝试，无隐式写入重试。空闲读取超时不是整个响应的总时限，Python退出也可能等待在途线程，因此CLI参数和预留时间不单独保证硬性墙钟终止。

Ubuntu workflow用GNU `timeout --signal=TERM --kill-after=10s 1190s`监督整个派生进程组：1190秒发送TERM，仍未退出时再过10秒发送不可捕获的KILL，以1200秒为进程监督上限；不使用会放弃子进程组控制的`--foreground`。21分钟步骤超时仅为外层兜底。超时或中断状态124、137、130、143按`publication_state=unknown`报告，不能声称最终PUT没有提交。最终PUT之前保存在私有临时目录的原子草稿可恢复精确final key和输入指纹，先读同键判断，再决定续跑；没有草稿时保留key未知，不能杜撰版本。预算停止保留已完成块，不提交部分最终摘要；可用相同命令续跑。原chips workflow在采集步骤后追加该派生步骤，`ALREADY_COMMITTED`仍可补齐已有批次的摘要，没有新增定时器或AWS常驻资源。

全部原分母股票有明确结果、来源未漂移、源码闭包不变且实际压缩认证响应估算不超过5.3MiB后，才可条件创建 `data/chips/daily/<dataset>/concentration.json`。首次本地运行默认只写草稿与检查点，必须明确 `--publish` 才请求最终对象。已存在的同源同规则结果先读回验证，不重做PUT。最终PUT可能已提交但响应或读回失败时，结果为 `publication_state=unknown`，带精确key和输入指纹；先读同键恢复，不能宣称没有发布或直接重放写入。成功完整读回才为 `verified`。

认证handler仅在原daily版本化GET白名单中新增精确 `concentration.json` 文件名，仍先检查Cognito和撤销状态，无新增写端点、代理路径、配置或IAM权限。前端只读取原daily manifest和它所指向的版本摘要，不在浏览器读取数千份股票帧。未知、未生成、读取失败、零入选分别展示。后台刷新失败保留上次完整结果、日期与筛选上下文，并显示恢复入口。

```sh
python -m backend.chips.concentration_runner --bucket EXISTING_PRIVATE_BUCKET --max-minutes 20 --workers 2 --out PRIVATE_DRAFT_PATH
```

`--dataset`可精确绑定初次运行；自然workflow使用当前指针并传入 `--publish`。日期、批次、股票池范围和发布结果必须分别读回。派生处理完成不把 `SITE_CATALOG_UNVERIFIED`升级为官方全市场名单已认证，也不证明软件等价、主力持仓、策略收益或用户人工验收。
